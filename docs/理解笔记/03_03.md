## 通用设置与评估口径

**训练平台：** 物理仿真器为 MuJoCo Warp；本文自行测量的计算成本使用 Lambda 按需实例上的 NVIDIA H100 80 GB SXM5。SONIC 的已报告训练成本来自其 L40 集群，不能误写为两者都在同型号 GPU 上训练。

**数据：** 主要大规模实验使用公开的 G1 重定向 BONES-SEED，经名称和几何可行性筛选后有 129514 个片段，时长约 264.56 小时。LAFAN1 受控实验使用 40 个片段、2.45 小时。速度接口实验另用从 LAFAN1 与 BONES-SEED 筛出的行走、跑步子集。

**指标：** 归一化回报是完整回合未折扣奖励之和除以其最大可能值；失败数依据指定终止条件统计。训练回报与保存检查点的固定协议评分不同，不能把图 4 各面板当成完全同一口径。

**统计说明：** 作者称多个随机种子下训练稳定，因此曲线未报告种子变化；这不等于论文给出了误差条、置信区间或具体显著性检验。速度接口实验明确每种策略只有一个训练种子。

依据：p.6，[S038](../../reader/paper.md#S038)、[S041–S042](../../reader/paper.md#S041)；p.7，[图 4 图注 C005](../../reader/paper.md#C005)；p.15–19，[S092](../../reader/paper.md#S092)、[S112](../../reader/paper.md#S112)、[S118](../../reader/paper.md#S118)。

## 1. 大规模整体比较：是否以更低成本覆盖更多动作

**要验证什么：** SuperMimic 相对已发表的大规模 PPO 流程，能否同时降低训练资源、改善跟踪表现，而不是只在少数动作上加速。

**怎样比较：** 以 SONIC 已发布检查点为主要基线，在相同的筛选后 BONES-SEED 基准上评估 129514 个动作。每个动作从首帧执行一次；评估时足部摩擦为 1.0，无域随机化、无观测噪声，物理过程确定。各策略仍采用自身执行器增益、动作缩放与观测构建方式。

**看什么：** 图 3(a) 是归一化回报随 GPU 小时数变化；表 A.8 与图 A.1 是失败动作数及其随训练变化。失败统一按 SuperMimic 的训练终止条件判定，不是直接使用 SONIC 自己的成功率口径。

| 配置或检查点 | 报告的训练配置 | 失败动作数 |
| --- | --- | --- |
| SONIC 已发布检查点 | 128 张 L40，7 天 | 179 |
| SuperMimic | 1 张 H100，3 小时 | 25 |
| SuperMimic | 2 张 H100，9.8 小时 | 0 |

附录还评估了 SONIC v1.1，失败 239 个；正文与主要比较表的 179 对应已发布检查点，不能混用。

**结果怎样支持主张：** 单 H100 在 3 小时内超过 SONIC 已发布检查点的回报，并减少失败动作。作者保守选取 3 小时这个报告点，而不是把曲线首次短暂超过基线的时刻当作达标时刻。论文据此概括实际耗时减少超过 50 倍、GPU 小时数减少超过 1000 倍。

**边界：** 两者数据量和 GPU 型号不同；这些是训练动作，因此 0 失败衡量训练库覆盖，不能等同于未见动作泛化。单 GPU 3 小时与双 GPU 9.8 小时是两个不同预算点。

依据：p.6，[S040–S041](../../reader/paper.md#S040)；p.7，[图 3 / C004](../../reader/paper.md#F003)；p.17–18，[S103–S105](../../reader/paper.md#S103)、[表 A.8](../../reader/paper.md#T009)、[图 A.1 / C018](../../reader/paper.md#F008)。

## 2. PPO-Sim 受控比较：共享更多设置后优势还在吗

**要验证什么：** 整体系统对比中的差异很多，因此需要另一个实验，尽量对齐任务与网络设置，比较在物理仿真器中运行 PPO 与通过世界模型更新策略。

**共享设置：** 使用 LAFAN1 的同一组 40 个动作，并对齐观测、奖励、终止、域随机化、行动者与评论家网络规模、评估协议。

**仍有的差别：** PPO-Sim 使用 BeyondMimic 的 PPO 超参数，每 GPU 8192 个并行环境；SuperMimic 是每 GPU 4096 个。PPO-Sim 使用仿真采样估计策略更新，SuperMimic 使用可微模型上的想象回报梯度。不能称为“除算法名外绝对相同”。

**结果：** SuperMimic 单 GPU 约 1.2 小时达到 0.82 评估回报；PPO-Sim 在 18 小时预算内没有达到。PPO-Sim 单、四、八 GPU 的最终回报约为 0.60、0.70、0.72，从四 GPU 增至八 GPU 收益很小。

**如何读图：** 图 4(a) 每个点是保存检查点在全部 40 个片段上的评分。这不是后续时域消融图中的训练回报。

**支持的结论：** 在更接近的任务与模型配置下，SuperMimic 仍体现明显的训练效率优势；该实验增强整体成本主张的说服力，但不能由此忽略实际保留的配置差别。

依据：p.6，[S042](../../reader/paper.md#S042)；p.7，[图 4(a) 与 C005](../../reader/paper.md#F004)。

## 3. 数据规模扫描：动作增加后会不会越来越难训练

**要验证什么：** 更多动作是否要求世界模型不断增加能力或付出近似按数据量线性增长的训练成本。

**怎样改变变量：** 在筛选后的 BONES-SEED 上使用 1、7、40、264 小时的子集。

**测什么：** 图 3(b) 测达到目标回报所需 GPU 小时数，图 3(c) 测世界模型 8 步状态预测误差。误差仅计状态，经过标称误差归一化，在线测于策略轨迹，不是米或百分比准确率。

**结果：** 数据量增加约 264 倍时，误差保持在约 0.007–0.011，达到目标回报的计算成本仅缓慢增长。

**作者如何解释：** §4.2 原文明确使用“shared body and contact dynamics”，认为新增动作提供关于共享身体与接触动力学的更多证据；图 3 图注也重复了这一解释。这里指包含接触效应的状态转移，不代表单独测量了接触力预测精度。原文见 [S046](../../reader/paper.md#S046)、[C004](../../reader/paper.md#C004)。

**边界：** 原文这段没有把扫描中的目标回报明确写成 LAFAN1 对照实验的 0.82，不应直接套用。图中趋势也不是对无限数据规模、复杂地形或任意接触场景的保证。

依据：p.6–7，[S043](../../reader/paper.md#S043)、[S046](../../reader/paper.md#S046)、[图 3(b,c) / C004](../../reader/paper.md#F003)；p.18，[S108](../../reader/paper.md#S108)。

## 4. 机制分析：模型快，与梯度有效，是两个问题

### 4.1 轨迹吞吐量比较

**对照与变量：** 比较学习世界模型与 MuJoCo Warp，横轴为并行环境数，纵轴为每秒控制步数。

**口径：** 一个控制步为 50 Hz 的一步；物理仿真用四个 5 ms 子步计算；世界模型使用训练中的 TF32 精度。

**结果：** 在实际使用的 2k–16k 批量范围，模型快超过 10 倍；64k 批量时快 62 倍，物理仿真吞吐已趋于平台。

**说明什么：** 模型生成训练轨迹更便宜，但这个图本身不能证明策略只需更少轨迹就能学会，也不是端到端训练时间的直接测速。

### 4.2 在世界模型上比较策略更新方法

**对照与任务：** 用 LAFAN1 中行走、跑步、冲刺动作，比较 SuperMimic 的行动者–评论家更新，与在世界模型轨迹上训练的 PPO-WM。

**PPO-WM 配置：** 4k×32、8k×24、8k×32、16k×32，分别表示并行轨迹数与每条步数；其中 16k×32 最好。曲线以想象步数为横轴，以训练回报为纵轴，并作居中移动平均。

**结果：** SuperMimic 用约少 64 倍的想象步数，达到 PPO-WM 最佳训练回报。

**说明什么：** 效率提升不只来自模型生成轨迹快，还包括策略更新对想象经验的使用效率。64 倍是该任务与该指标下的步数差异，不是所有数据集上的统一加速系数。不能把吞吐量倍数与步数倍数直接相乘成新的端到端加速主张。

依据：p.7–8，[S047–S048](../../reader/paper.md#S047)、[图 5 与完整图注 C006](../../reader/paper.md#F005)。

## 5. 评论家消融：短时域能否学会，扰动后能否恢复

**要验证什么：** 评论家是否只是附加网络，还是确实能补足短想象窗口看不到的远期后果。

**怎样改变变量：** 在 LAFAN1 上，比较有、无评论家，并扫描想象时域 H=8、16、32、64、128。图 4(b) 是最终训练回报，图 4(c) 是训练回报达到 0.82 所需小时数。

**结果：** H=8 时两种版本都未达标；H=16 时无评论家未达标，有评论家能达到类似无评论家 H=32 的表现；带评论家 H=32 达标最快。H 从 64 增至 128，达标耗时接近三倍，最终回报还下降。

“失败”在这里指该时域下没有达到指定回报，不应擅自写成程序报错或数值崩溃。

**另外做的行为测试：** 在仿真中保持静态 T 字姿态，对回报相当的策略施加 0.5–4 m/s 的速度扰动。带评论家策略在 0.5–2.4 秒内稳定；无评论家策略即使在 0.5 m/s 下仍持续踉跄，4 m/s 时跌倒。

**边界：** m/s 是速度扰动的量级，不是牛顿单位的外力大小。该试验证明特定设置中的恢复行为改善，不是任意扰动下的稳定性定理。正文这段也未展开所有扰动方向、重复次数或误差统计。

依据：p.7，[图 4(b,c) / C005](../../reader/paper.md#F004)；p.8，[S050](../../reader/paper.md#S050)。

## 6. 实机部署：一个策略能执行哪些动作

**要验证什么：** 在仿真数据和学习世界模型上训练出的策略，能否迁移到真实 Unitree G1。

**展示内容：** 同一个通用运动跟踪器、不逐动作调参，执行跳步、侧滚、90° 翻转、原地 360° 翻转。侧滚涉及躯干和四肢接触地面，因此不是只测试直立行走。

**支持的结论：** 本方法训练出的控制策略确实具有实机可部署性，并覆盖多种接触和动作形态。

**边界：** 论文在这一部分主要给出动作展示，没有列出这四类动作的完整实机重复成功率表；不能据此声称 129514 个动作都逐一在真实机器人上实现，也不能将侧滚展示等同于接触力预测精度测试。

依据：p.8，[S052](../../reader/paper.md#S052)；p.9，[图 6 与 C007](../../reader/paper.md#F006)。

## 7. 下游速度接口：任务奖励训练与蒸馏相比如何

**要验证什么：** 共享世界模型与解码器后，速度接口直接优化自身任务奖励，是否比只利用参考动作跟踪信号更适合速度指令任务。

**两种训练：** 各自从零训练 100000 次迭代，并与运动跟踪接口并行；共享结构下，RL 版本使用速度奖励与跌倒终止，蒸馏基线使用运动跟踪奖励与对应终止条件。两者不只是换一个损失名称，奖励、终止与指令安排存在具体差别。

**数据与批量：** 使用 LAFAN1 与 BONES-SEED 的行走、跑步子集；4096 个仿真环境的一半以及每个想象批次的一半分配给速度接口。

**指令：** 目标由前后、左右平面速度及偏航角速度组成。RL 版本混合参考来源与均匀随机指令；具体范围、切换与潜在对齐损失见 [02_08](02_08.md)。下游任务回报更新速度编码器，不更新共享解码器权重。

**测试协议：** 从站立开始，保持一个指令 5 秒；每指令做 4 次试验，取最后 2 秒计算相对稳态误差，再对未跌倒试验取中位数。在三个指令平面上各用 15×15 网格，去掉零指令，得到 672 个阶跃响应。图 7 把超过 0.9 的误差截在 0.9，四次全跌倒也画到该上限。

**结果：** RL 编码器在 650 个响应上误差更低，蒸馏在 15 个上更低；相对误差中位数分别为 0.16 与 0.49。蒸馏在 7 个快速转向指令上四次全跌倒，这些区域在动作库中几乎没有数据。

**边界：** 每种策略只有一个训练种子，作者将其定位为初步研究。也未验证让速度任务奖励同时更新解码器后，是否会进一步改善或影响运动跟踪。

依据：p.8–9，[S054](../../reader/paper.md#S054)、[图 7 / C008](../../reader/paper.md#F007)；p.18–19，[S112–S118](../../reader/paper.md#S112)；p.9，[S058](../../reader/paper.md#S058)。

## 阅读实验时最应该分清什么

本文表 1 是相关工作训练策略对照，不等于把表中所有方法都作为实验基线重跑。真正的主要比较包括 SONIC 检查点、PPO-Sim、PPO-WM、有无评论家，以及 RL 速度编码器与蒸馏基线；各自回答的问题不同。

“一个模型共享动力学”是方法解释；模型误差、训练曲线、失败数量、抗推行为和实机部署，才分别构成支持它及整体方法的实验链条。应按各实验的设置与指标判断，不能只凭几个最终数字合并成一个无条件结论。
